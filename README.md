# His&Her Lucky Spin — ชุดสำหรับทำงานใหม่

หน้าตาเว็บดึงมาจากระบบของงานสหกรุ๊ปแฟร์ครั้งที่ 30 ส่วนเซิร์ฟเวอร์เขียนใหม่ให้ทำงานแบบเดียวกัน
(ของเดิมไม่ได้เก็บโค้ดไว้ใน Git จึงดึงฝั่งเซิร์ฟเวอร์ออกมาไม่ได้)

## มีอะไรบ้าง

| ส่วน | การทำงาน |
|---|---|
| หน้ากรอกรหัส (`/`) | กรอกรหัสสมาชิก แล้วระบบเช็กว่าเคยเล่นหรือยัง |
| หน้าวงล้อ (`/game.html`) | หมุนวงล้อ เซิร์ฟเวอร์เป็นคนสุ่มรางวัล (โกงจากหน้าเว็บไม่ได้) |
| หลังบ้าน (`/admin`) | ดูยอดผู้เล่น แก้สต็อกรางวัล ลบรายการ Export CSV และรีเซ็ต |
| กติกา | 1 รหัสเล่นได้ 1 ครั้ง สุ่มถ่วงน้ำหนักตามสต็อกที่เหลือ (ของเหลือมากออกบ่อยกว่า) รางวัลที่หมดจะหายจากวงล้อเอง |

> ⚠️ กติกาการสุ่มของระบบเดิมดูจากภายนอกไม่ได้ ระบบนี้ใช้วิธีสุ่มถ่วงน้ำหนักตามสต็อกแทน
> ถ้าอยากกำหนดโอกาสออกเอง (เช่น รางวัลใหญ่ออกยาก) แจ้งได้ จะเพิ่มให้

## เปลี่ยนเป็นงานใหม่: แก้ 2 จุด

**1. ไฟล์ `event.config.json`**: ตอนนี้ยังเป็นค่าของงานครั้งที่ 30 ให้แก้ชื่องาน วันที่ สถานที่ คำโปรย และรายการรางวัลกับสต็อก

- `theme` = ธีมสี ตอนนี้ใช้ `icc-fair` (ไฟล์ `views/theme-icc-fair.css`) ถ้าเว้นว่างจะใช้โทนแดง/ท้องฟ้าแบบงานสหกรุ๊ปแฟร์
- `tagline` = คำโปรย ใช้ `\n` เพื่อขึ้นบรรทัดใหม่
- `badgeLines` = ตัวอักษรในวงกลมข้างชื่องาน (ถ้าไม่ใช้ให้ใส่ `[]`)
- `saturation` = ความสดของสี (1 = ปกติ ระบบเดิมใช้ 0.7 ช่วงไว้อาลัย)
- `memberIdPattern` = รูปแบบรหัสสมาชิกที่ยอมรับ (เว้นว่าง = รับทุกรหัส)
  เช่น `"^[0-9]{10}$"` = ต้องเป็นตัวเลข 10 หลัก
- ⚠️ `name` ของแต่ละรางวัลต้องไม่ซ้ำกัน

**2. ภาพ**

- `public/prizes/` = ภาพรางวัล (ชื่อไฟล์ต้องตรงกับ `file` ใน config แนะนำ PNG สี่เหลี่ยมจัตุรัส พื้นโปร่งใส)
- `public/assets/` = โลโก้ His&Her และมาสคอต (ถ้าจะเปลี่ยน ให้ใช้ชื่อไฟล์เดิม)

## ทดลองในเครื่อง (ต้องมี Node.js 20+)

```
ADMIN_PASSWORD=ทดสอบ node server.js
```

แล้วเปิด http://localhost:3000 (ข้อมูลเก็บในหน่วยความจำ ปิดโปรแกรมแล้วหาย)

## ขึ้นระบบใน region Thailand (แนะนำ: ใช้ Lambda เพราะ Amplify ไม่มีใน Thailand)

ใน AWS Console เปลี่ยน region เป็น **Asia Pacific (Thailand)** แล้วเปิด **CloudShell** → Upload zip นี้ แล้วรัน:

```
unzip -q hisher-luckyspin.zip && cd hisher-luckyspin
bash setup-role-th.sh          # ครั้งแรกครั้งเดียว: สร้างสิทธิ์ (ผู้ดูแลบัญชีเป็นคนรัน)
bash deploy-th.sh iccfair2026  # ได้ลิงก์ ...lambda-url.ap-southeast-7.on.aws
```

แก้รางวัลหรือหน้าเว็บแล้ว รัน `bash deploy-th.sh iccfair2026` ซ้ำได้ ข้อมูลผู้เล่นไม่หาย

## ขึ้นระบบจริงบน AWS ด้วย Amplify (region Sydney — ทางเลือกเดิม) (บัญชี ICC - His & Her, region Sydney)

1. คัดลอก `.env.example` เป็น `.env` แล้วตั้ง `ADMIN_PASSWORD=` (ห้ามใช้ testpass)
2. ใน AWS Console เปลี่ยน region เป็น **Asia Pacific (Sydney)** แล้วกดไอคอน **CloudShell** `>_` ที่แถบบน
3. ใน CloudShell ไปที่ Actions → **Upload file** แล้วอัปโหลด zip ชุดนี้ จากนั้นรัน:
   ```
   unzip -q hisher-luckyspin.zip && cd hisher-luckyspin
   bash deploy.sh ชื่องานใหม่-luckydraw
   ```
   (ชื่อ branch ใช้ได้เฉพาะ a-z, 0-9 และ - เช่น `bigsale2027-luckydraw`)
4. สคริปต์จะสร้างตาราง DynamoDB และ branch ใหม่ในแอปเดิม `d2g5ldrtarqy48`
   แล้วแสดงลิงก์ใหม่ให้ งานครั้งที่ 30 ไม่ถูกแตะ

### สิทธิ์ DynamoDB (ทำครั้งแรกครั้งเดียว)

แอปต้องมีสิทธิ์อ่านและเขียนตาราง โดยไปที่ Amplify → แอป → **App settings → IAM roles**

- ถ้ามี **Compute role** อยู่แล้ว ให้กดชื่อ role แล้วไปที่ IAM → Add permissions → Create inline policy → JSON
  และวางเนื้อหาจากไฟล์ `iam-policy-dynamodb.json`
- ถ้ายังไม่มี ให้สร้าง role ใน IAM (trusted entity: Amplify) แนบ policy เดียวกัน แล้วเลือก role นี้เป็น Compute role

ถ้าหน้า `/api/stock` ขึ้น `server_error` ส่วนใหญ่เป็นเพราะสิทธิ์ข้อนี้
